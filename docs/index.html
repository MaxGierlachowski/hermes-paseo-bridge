Your agent finishes. The chat carries on.

When a Paseo agent that Hermes started finishes or needs a permission, the Hermes session that started it takes a new turn, with its whole history. Slack threads, Desktop and TUI chats alike.

Why

A Hermes webhook route answers an agent event in a separate run without the conversation's context, and cannot reach Desktop or TUI chats. This plugin feeds the event into the session that started the agent, so that session continues itself.

🏷️

Automatic back-reference

A pre_tool_call hook labels every agent with the calling session's key. Nothing for the model to remember.

↩︎

Same session, new turn

inject_message with that key: the session summarises, answers the permission or carries on.

⏳

Busy is fine

A session in the middle of a turn queues the update and runs it next. Nothing is interrupted.

①

Exactly once

Deliveries and events are deduplicated on disk, across gateway restarts and paseo-mcp retries.

≋

Calm

Events of one session within seconds become one turn, and a per-session rate limit merges bursts.

⚑

Nothing lost quietly

No key, unknown session, other profile: log, forward to a webhook or a home chat, with the reason stored.

How it works

Two small pieces inside the Hermes gateway, connected through paseo-mcp's signed webhooks.

01 · LABEL

Know the session

The hook reads the turn's HERMES_SESSION_KEY and adds it, with profile and session id, to the agent's labels.

02 · RECEIVE

Verify and store

Standard Webhooks signature, then delivery and events go to SQLite before the request is answered.

03 · PACE

Coalesce

Events per session wait a few seconds for company; a rate limit holds bursts back.

04 · CONTINUE

Inject

One compact message: title, id, outcome, permission details, the agent's last words marked as untrusted.

Install

Hermes with plugin injection, and paseo-mcp 0.4 or newer in Hermes and in Paseo.

  1. Install the plugin
    hermes plugins install MaxGierlachowski/hermes-paseo-bridge --enable
  2. Allow it to start turns
    plugins:
  entries:
    hermes-paseo-bridge:
      allow_gateway_injection: true
    In the profile's config.yaml. Put a long random HERMES_PASEO_BRIDGE_SECRET into its .env, then restart the gateway once.
  3. Point paseo-mcp at itPaseo → Settings → Plugins → Paseo MCP → Webhooks: URL http://127.0.0.1:8645/paseo/events, signature Standard Webhooks, import the secret, types agent.turn_ended and agent.permission_requested, label origin=hermes. Press Test.
  4. Use Hermes as beforeAsk it to start an agent. When the agent is done, the chat continues. /paseo-bridge shows the status.

Settings that matter

All optional, under plugins.entries.hermes-paseo-bridge.settings. The full list is in the README.

KeyDefaultMeaning
listen_port8645Loopback port of the receiver; one per Hermes profile.
filter_labelsorigin: hermesOnly events of agents with all these labels.
event_typesturn_ended, permission_requestedWhich events become a turn.
coalesce_seconds5Wait for more events of the same session.
max_turns_per_minute6Per session; the rest is merged into the next turn.
fallback.modeloglog, forward (signed POST to a URL) or session (a home chat).

Desktop and TUI chats must be open. Hermes injects into a local session only while a client holds it; otherwise the update takes the fallback.
